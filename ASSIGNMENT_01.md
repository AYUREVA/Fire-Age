# Практика №1 — Сделай игру за 80 минут

## Цель

К концу пары должна существовать **публичная ссылка**, которую можно отправить другому человеку, и он сможет начать играть без объяснений автора.

## На практике

### 0–10 минут — 10 идей

Запиши 10 коротких идей по формуле:

> Игрок делает **X**, чтобы добиться **Y**, пока ему мешает **Z**.

### 10–15 минут — оставить одну

Для трёх лучших идей спроси:

- можно сделать одному?
- нужна сложная графика?
- нужен сервер?
- сколько механик?
- можно получить playable сегодня?

Выбери проект с **самым коротким путём до работающей игры**.

### 15–20 минут — описать игру

Ответь:

1. Кто или что игрок?
2. Что он делает большую часть времени?
3. Зачем?
4. Что мешает?
5. Когда игра заканчивается?

### 20–55 минут — сделать playable prototype

Измени `src/game/GameScene.ts` так, чтобы появились:

- игровое действие;
- реакция игры;
- цель / результат;
- проблема / препятствие.

Не трать время на красивое меню и финальную графику.

### 55–65 минут — Git + публикация

Проверь:

```bash
npm run typecheck
npm run build
```

Commit + Push.

Добейся рабочей публичной ссылки через GitHub Pages.

### 65–75 минут — первый игрок

Дай ссылку другому студенту.

**Ничего не объясняй.**

Запиши минимум 3 наблюдения за реальным поведением игрока.

### 75–80 минут — план домашней части

Запиши, что нужно исправить и доделать.

# Домашняя работа №1 — Gray-box Prototype

К следующему занятию:

- [ ] игра запускается по публичной ссылке;
- [ ] понятна без объяснения автора;
- [ ] есть основное действие;
- [ ] есть feedback;
- [ ] есть цель / счёт / иной понятный результат;
- [ ] есть препятствие, риск или условие поражения;
- [ ] можно начать заново;
- [ ] можно осмысленно играть 1–2 минуты;
- [ ] обновлён `README.md`;
- [ ] заполнен `CHANGELOG.md`.

## Что сдавать

1. Ссылку на игру.
2. Ссылку на GitHub-репозиторий.
3. `README.md` с описанием игры и управления.
4. `CHANGELOG.md` с коротким отчётом.
